# 入境游旅行规划 Skill（Inbound Travel Planner）

## 0. 这个 Skill 是什么

一个**路由式攻略生成引擎**。它不预存"北京 5 天怎么玩"之类的成品答案，而是把
「外国人在华旅行」拆成三层可复用的能力，按用户意图动态组装：

1. **契约层（contracts/）** —— 所有产出必须遵守的"输出格式 + 质检标准 + 信息标注纪律"。
2. **知识层（knowledge/ + reference/）** —— 跨场景复用的原子能力模块与速查资料。
3. **意图层（workflows/）** —— 8 类用户意图各自的"泛化工作流骨架"。

**设计原则：工作流是泛化的，知识是共享的，场景是拼装的。**
一个"带轮椅的父母去西安 5 天"的需求 = 人群骨架 × 单城骨架 ＋ 无障碍/交通/住宿/预约
等知识模块 ＋ 契约约束。

## 1. 快速开始

```
输入：外国人在成都 5 天 4 晚，想吃美食、看熊猫，不会中文
  ↓
1) 解析槽位：{地点:成都, 天数:5, 人群:首次来华, 主题:美食+熊猫, 语言:不会中文}
2) 路由：主 W1（单城），修饰 W3（美食/熊猫主题）
3) 取骨架：workflows/W1_single-city.md
4) 加载知识：K01 K02 K03 K05 K06 K08 K09 K10 K11（+K12 体力）
5) 取速查：reference/key-phrases.md、reference/etiquette-and-taboos.md
6) 按 contracts/output-contract.md 组装五段式 + 填 12 模块自查表 + 打标注
7) 过质检 → 输出
```

> 完整成型样例见 `examples/example-chengdu-5d.md`，可用于校准格式。

## 2. 路由决策树（核心）

**第一步：把用户输入套进下面 8 类意图，命中即路由。**

| 编号 | 意图类型 | 典型输入信号 | 路由到 |
|---|---|---|---|
| **W1** | 单点城市/区域行程 | 单一城市或紧密城市群 + 天数，如"北京 5 天" | `workflows/W1_single-city.md` |
| **W2** | 跨城市线路 | 2 个以上相距较远的城市 + 天数，如"北京-西安-上海 10 天" | `workflows/W2_multi-city.md` |
| **W3** | 主题深度 | 主题词：美食/博物馆/古镇/茶/功夫/徒步/骑行/摄影/非遗…… | `workflows/W3_theme-route.md` |
| **W4** | 人群细分 | 人群画像：老人/亲子/背包客/残障/素食/穆斯林/LGBTQ+/数字游民/记者…… | `workflows/W4_persona.md` |
| **W5** | 入境实务操作 | "如何……"的单一动作：签证/绑卡/买卡/订票/打车/点餐/报警…… | `workflows/W5_howto.md` |
| **W6** | 约束条件规划 | 硬约束：预算 X 元 / 只有 N 天短途 / 某季节 / 春节国庆 | `workflows/W6_constraint.md` |
| **W7** | 特殊入境与交通方式 | 邮轮/陆路口岸/转机/自驾/大巴/绿皮车/宠物/处方药 | `workflows/W7_special-entry.md` |
| **W8** | 决策对比 | "A vs B / 选哪个 / 怎么选" | `workflows/W8_comparison.md` |

**第二步：复合意图要"主工作流 + 修饰工作流"叠加。**

- "带 5 岁孩子的外国家庭 10 天" → 主 **W4（人群）**，内部调用 W1 的逐日骨架。
- "外国残障人士（轮椅）中国 10 天无障碍攻略" → 主 **W4**，强约束 K12（无障碍）。
- "外国人中国 7 天预算 5000 元" → 主 **W6（约束）** + W1 行程骨架。
- "外国人在西藏拉萨 5 天（含入藏函）" → 主 **W1** + **W7 的证件特别通道分支**。
- "外国人如何订高铁票：证件、取票、进站" → **W5**（纯实务，无行程）。

**第三步：无论命中哪类意图，都必须回挂知识层。**

工作流只定义"讲什么顺序、用什么结构"，具体事实与操作细节一律从
`knowledge/K01–K12` 取用，避免各工作流重复造轮子。

**意图判定口诀：**
- 出现"如何……" → **W5**，哪怕句中有城市。
- 出现"A vs B / 选哪个" → **W8**。
- 有城市 + 天数、无其他强信号 → **W1 / W2**（看是否跨城）。
- 人群 / 主题 / 预算 / 季节是**修饰**，叠在行程骨架上。

## 3. 知识层索引（K01–K12）

这 12 个模块是"信息覆盖自查表"的 12 行，也是所有工作流的共享素材库。

| 模块 | 主题 | 文件 | 何时必加载 |
|---|---|---|---|
| K01 | 签证 / 免签 | `knowledge/K01_visa.md` | 首次来华、跨口岸、停留期敏感 |
| K02 | 入境准备（行前 + 边检海关） | `knowledge/K02_entry-prep.md` | 几乎总是 |
| K03 | 外卡支付与支付宝/微信绑定 | `knowledge/K03_payment.md` | 几乎总是 |
| K04 | 手机卡 / eSIM / 上网 / 网络合规 | `knowledge/K04_connectivity.md` | 天数 ≥ 3 或提到通讯 |
| K05 | 语言翻译 | `knowledge/K05_language.md` | 不会中文者 |
| K06 | 住宿登记（酒店/民宿/派出所） | `knowledge/K06_accommodation.md` | 有住宿安排 |
| K07 | 高铁 / 飞机购票证件 | `knowledge/K07_rail-flight.md` | 有城际移动 |
| K08 | 景点预约证件 | `knowledge/K08_attraction-booking.md` | 有热门景点 |
| K09 | 餐饮英文服务 / 过敏忌口 | `knowledge/K09_dining.md` | 几乎总是 |
| K10 | 安全应急（报警/医疗/使领馆/骗局） | `knowledge/K10_safety.md` | 几乎总是 |
| K11 | 预算拆解 | `knowledge/K11_budget.md` | 有预算意图或 ≥ 3 天 |
| K12 | 步行强度 / 体力 / 无障碍 | `knowledge/K12_walking.md` | 有老人儿童残障或高强度线路 |

**加载规则（省 token）：** 先按意图选 3–5 个**必加载**模块，其余模块在自查表里
标"弱覆盖 / 不适用"即可，不必展开。

## 4. 参考层索引（速查资料）

| 文件 | 内容 | 何时取用 |
|---|---|---|
| `reference/emergency-and-contacts.md` | 紧急号码、就医渠道、护照丢失流程、求助热线 | 写"安全应急"章 |
| `reference/key-phrases.md` | 中英对照高频短语卡（生存/交通/点餐/住宿/应急） | 写"语言""点餐"章 |
| `reference/etiquette-and-taboos.md` | 礼仪、禁忌、给小费、拍照、宗教场所禁忌 | 写"文化礼仪"章 |
| `reference/city-quickref.md` | 主要城市速查（机场代码/必看/季节/步行强度/英语友好度） | 写城市行程时 |

> 参考层只放**结构性与稳定信息**；任何价格、时刻、名单仍走"需实时检索确认"。

## 5. 契约层索引（输出与质检）

| 文件 | 作用 | 强制 |
|---|---|---|
| `contracts/output-contract.md` | 五段式标准结构 + 12 模块自查表 + 标注纪律 | 是 |
| `contracts/routing-rules.md` | 意图判定边界、复合意图叠加、追问策略、批量规则 | 是 |

**无论生成哪一篇攻略，最终产出必须同时满足：**
1. 严格五段式（`需求理解 / 完整攻略 / 信息覆盖自查表 / 需实时检索确认的事项 / 缺失项与需追问用户的信息`）；
2. 12 模块自查表逐行填写，不得空行；
3. 每条关键事实后缀 `[通用知识]` 或 `[需实时检索确认]`；
4. 凡涉及票价、时刻、名单、开放时间、政策细则 —— **一律标"需实时检索确认"，不编造数值**。

## 6. 组装流程（执行顺序）

```
1. 解析输入 → 提取 {地点, 天数, 人群, 主题, 预算, 季节, 入境方式, 对比项}
2. 用 §2 路由决策树 → 得到 主工作流 + 修饰工作流
3. 打开对应 workflows/*.md → 拿到该意图的"章节骨架"
4. 按 §3 加载 3–5 个 knowledge/K*.md → 填充事实与操作细节
5. 按 §4 取用 reference/*.md → 补速查数据
6. 按 contracts/output-contract.md 组装五段式 + 填 12 模块自查表
7. 过质检：标注纪律 / 实时检索项是否齐全 / 缺失项是否列全
8. 输出
```

## 8. 边界与免责

- 本 Skill 产出**方法论与操作路径**，不提供实时数据（票价/时刻/名单以官方实时为准）。
- 不替代签证、医疗、法律等专业意见；涉及政策一律引导用户到官方渠道复核。
- 所有时效性信息标注 `[需实时检索确认]`，是硬性质量要求，不可省略。
- 涉及网络访问合规、无人机、国际驾照、处方药、宠物等敏感事项，按中国法律法规如实提示。
