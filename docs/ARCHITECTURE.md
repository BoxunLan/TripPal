# 框架说明 — 旅行 Agent 垂直切片

一句话：**一条 `POST /plan` 请求 = 一次确定性槽位体检 + 一次场景分类 + 一次分层检索 +
一次生成 + 一次三项校验（最多回炉一轮）**。全部编排参数写在 `routes.yaml`，
代码里不硬编码业务规则。

---

## 1. 四层结构

| 层 | 内容 | 关键约定 |
|---|---|---|
| **接入层** | FastAPI：`POST /plan`、`GET /health`、`GET /`（托管 `web/index.html`）、`GET /session/{id}`（会话快照）、`POST /plan/start` + `GET /plan/progress/{id}`、`POST /plan/stream`（NDJSON） | 页面走「起步 + 短轮询」拿进度；接口地址由 `resolveBase()` 自动探测，**不假设同源**（预览面板会把页面拷到随机端口） |
| **编排层** | LangGraph 状态图，七个主干节点 + `realtime` / `knowledge` / `guide` 三条旁路 | 主干顺序不可改，有测试钉住（见 §3）；三条旁路都在 `clarify` 后短路 |
| **能力层** | LLM（分类 `ecnu-plus` / 生成 `ecnu-max`，常识作答复用生成角色）、Embedding（1024 维）、向量库（memory / pgvector 双实现）、工具 ×3、校验 ×3 | 所有外部依赖经 `deps.py` 注入，测试整层换成假实现。**实时旁路不用模型也不用向量**；常识旁路不用向量、用一次模型（见下） |
| **配置与数据层** | `routes.yaml`（11 节）、`seed/*.jsonl`（**170 条**，2026-10-05 起不再含出境日本内容）、`prompts/*.md`（8 份）、进程内会话（槽位 + 轮次轨迹 + 审计 JSONL） | 改 `routes.yaml` 要重启；改 `web/index.html` 不用 |

## 3. 节点链路

```
主干  clarify → classify → route → retrieve → generate → validate → output
旁路  clarify → realtime  → output      实时事实（会变：几点升旗、今天开不开门）
旁路  clarify → knowledge → output      静态常识与目的地咨询（西湖有多大、厦门有什么好吃的）
旁路  clarify → guide     → output      寒暄 / 元问题（你好、谢谢、刚才我说了什么）
```

**旁路存在的理由**（改之前先读）：用户输入「天安门什么时候升旗」，主干把它当行程请求做槽位体检，
判为缺 `destination / date_range / budget / party`，于是回了「想去的城市或国家是哪里？计划玩几天？
预算是多少？一行几个人？」—— 四个问题全问错了方向。事实问询不需要那四个槽位，
只需要「问的是什么 + 知识库有没有答案 + 去哪查」。

同一个错误有**三种形态**，各配一道闸门（`app/intent.py`，**都不调模型**）：

| 形态 | 例子 | 闸门 | 为什么需要再补一道 |
|---|---|---|---|
| 会变的事实 | 天安门什么时候升旗 | `detect_realtime_intent` | — |
| 不变的事实 | 西湖有多大 | `detect_knowledge_intent` | 它不含任何时间/开放/天气/交通词 → 实时闸门不接管 → 照样掉回槽位体检 |
| 目的地咨询 | 厦门有什么好吃的 | 同上，**咨询兜底**路径 | 连度量 / 定义类正则都不命中 → 上一版又掉回槽位体检，被回以「缺 日期/预算/人数」 |
| 是非问 | 华东师范大学**是不是**有个新校区在那里 | 同上，**骨架正则**路径 | 清单里只有「有没有 / 是否有」，漏了系词「是不是」；学校又不是词典里的地名 → 三道闸门全灭 → 四连问（2026-10-04 用户报） |

每道闸门的条件：命中 `routes.yaml::intents.<闸门>.triggers` 的正则，**且**当前这句没抽出任何行程槽位
（`days / budget / daily_budget / party_size / date_range / start_date`）。常识闸门另有第三条让路：
句中出现规划动词（「厦门怎么玩」）→ 仍在排行程。

触发词按**问句骨架**收（有无 / 是非 / 列举 / 度量 / 时间 / 定义 / 咨询），不逐词补 —— 同一类问法
（「是不是 X」「X 要不要预约」）无穷多，逐词补必然再漏，而每漏一次就是一次四连问。

常识闸门的**兜底路径**（`consult_fallback`）：正则全不命中时，只要句子里有可解析的目的地、
且是疑问 / 咨询语气，也算常识问询。判据故意不看「有没有规划动词」的反面 ——
没有疑问语气的「去厦门」仍在排行程，不能被这条路径吞掉。

**主体提取的退化处理**：命中片段在句中 → 前半截就是主体（「华东师范大学是不是…」→「华东师范大学」）；
命中片段在**句首** → 只能拿命中片段当主体，那对「离境退税」这类主题名是对的，对纯功能词骨架
（`intent._FUNCTION_SKELETON`：「是不是」「有没有」…）就是噪声 —— 这种退化一律退回槽位体检，
不假装答了一个句法成分。

让路规则的作用：「去厦门 5 天，预算 8000，顺便问下鼓浪屿几点开门」仍走主干。

| 节点 | 做什么 | 不做什么 |
|---|---|---|
| `clarify` | **先判追问承接**（短、无地名、带疑问 → 接上一轮主体与实词）与**方位指代**（「那里」→ 上一轮的地点）→ **再判意图**（寒暄 → 实时 → 常识 → 才做槽位体检），缺槽就出追问 | **不检索、不调模型**（0.0s 返回） |
| `realtime` | 旁路：`store.scan` 扫实时层 → 相关性闸门 → 时效闸门 | **不调模型、不走向量**（实测 6–28ms） |
| `knowledge` | 旁路：`store.scan` 扫 scene/general → **地点作用域过滤** → 相关性闸门 → **按问句词面打分排序**（`TF×IDF` + 相对截断）→ **模型通用常识作答** → 装配答案 + 复核入口 | **不走向量**；会调一次模型（实测 0.6–0.9s）—— 长尾常识没有本地资料能覆盖 |
| `guide` | 旁路：寒暄（问候/致谢/道别/关于我）调一次模型给 1–2 句 + 邀请；`recall`（「刚才我说了什么」）**由会话历史确定性作答，不调模型** | 不检索、**绝不问四问** |
| `classify` | 小模型打场景标签（family/budget/roadtrip/visa/general），可多标签 | 不做槽位重写以外的决策 |
| `route` | 置信度门控 + 融合，产出 `RouteConfig`（提示词、层配额、工具白名单、guardrail、输出语言） | 不检索 |
| `retrieve` | 元数据预过滤 → 向量召回 → 按层配额截断 | 不排序改写 |
| `generate` | 一次生成 + 产物组装（逐日/预算/清单/引用） | 不校验 |
| `validate` | 并行三项校验 + 严重分级 + 回环计数 | 不改写内容（只标记） |
| `output` | 组装最终响应（`plan` / `clarify` / `realtime` / `answer` / `degraded`） | — |

### 条件边（图里唯一的分支）

| 边 | 判据 | 结果 |
|---|---|---|
| `clarify_gate` | `decision == "clarify"` | 短路到 `output`，出追问 |
| `clarify_gate` | `decision == "realtime"` | 走 `realtime` 旁路 → `output`（不碰 classify/route/retrieve/generate/validate） |
| `clarify_gate` | `decision == "knowledge"` | 走 `knowledge` 旁路 → `output`（同上五步不亮） |
| `route_gate` | `decision == "clarify"`（路由阶段二次判定） | 短路到 `output` |
| `validate_gate` | 任一 check 的 `status == "repair"` | 回 `generate`，**最多 1 轮**（`max_repair_rounds` 被校验器钉死为 1） |

回环计数在 `validate_node` 内部做，条件边只看「有没有 repair」。

### 事实信息的两道闸门（`app/realtime.py`）

| 闸门 | 规则 | 挡掉什么 |
|---|---|---|
| 相关性 | 主体比地点更具体时（天安门 vs 北京）→ 正文必须出现主体；主体就是地点时 → 条目的 `metadata.kind` 必须在该类型名单里 | 「北京明天天气」召回 destination=北京 的升旗条目 |
| 时效 | `fresh_until < today` 的实时条目丢弃并计数 | 过期攻略冒充当日状态 |

两条结果都合法：**查到没过期的来源**，或**明确说查不到 + 给权威入口**。
中间态（拿旧材料编一个时刻）是最坏的结果 —— 它读起来像答案。

### 常识问询：为什么这一层允许调模型（`app/knowledge.py`）

实时链路的红线是「事实断言不由模型生成」—— 因为**时刻会变**，模型只能猜
（今天的升旗时间是 06:06 还是 06:07，它不知道）。面积 / 海拔 / 历史年份不属于这一类：
它们稳定，且是模型语料里最扎实的部分 —— 而这类长尾常识**没有任何本地资料库能覆盖**。
所以这一层的分工是：

| 规矩 | 理由 |
|---|---|
| **不走向量**（`store.scan` 元数据扫描） | 相似度为了凑 top_k 一定会返回东西，而那些东西会被读成答案 |
| **相关性闸门** | 主体必须真的出现在正文里（或条目目的地就是主体）—— 库里对主体一无所知就返回空，不拿别的话题凑数 |
| **相关条目跟着问句走**（`search_knowledge`） | 三段式：**① 候选池**（沾主体 **或** 命中问句实词）→ **② 地点作用域**（主体是具体地点时滤掉异城异国条目，问上海不列北京/厦门）→ **③ 词面打分排序**（实词按出现次数 × **IDF**；地名/通用主体**不给分**，只做同分兜底）。`limit` 是**上限不是配额**（相对截断 `REL_KEEP`），库里没有就返回空。排序里必须有问句，否则同一个城市的任何问题都列出同样那几条 |
| **实词抽取要先折「V不V」**（`_query_terms` / `_VV_FOLD`） | 「收不收费」直接取 bigram 会切出**跨骨架假词**「收不 / 不收」，它们会命中无关条目（实测：「收不」命中 eSIM 条目的「**收不**到短信」→ 一条讲上网的条目被列进博物馆问题的相关条目）。折成实义部分（收费 / 门票 / 预约）后假词与误召回一起消失；折完只剩单字（贵不贵→贵）就诚实地**无实词 → 相关条目为空** |
| **答案由模型给，但必须标注** | `kn.general_knowledge` 明说「未经本知识库核实」，不冒充已核实结论 |
| **必须给复核入口**（`verify`） | **先给命中条目自带的官方页面**（那是这一问的权威落点），再按**主体 + 焦点**拼一条检索链接（标题不再是光秃秃的「上海」，见 `display_topic`）。给一条链接比替用户担保更诚实 |
| **时效性信息拒答** | `prompts/answer.md` 规则 4：时刻 / 票价 / 开放状态 / 天气一律留空。这是防幻觉的**双保险** —— 即使意图闸门漏了，「天安门什么时候升旗」也不会在这条链路上被编出一个时刻 |

命中的知识库条目**不宣称是答案**（文案写明「不是这个问题的答案」）——
问「鼓浪屿有多大」命中的大多是行程攻略，谈的是怎么玩。相关材料冒充答案同样是错的。

### 会话记忆：追问承接（`app/session.py` + `app/intent.py::carry_over_subject`）

真 bug（2026-10-04 用户报「一是没有对话记忆」）：问完「上海有没有免费的博物馆」再问
「那要预约吗？」，系统回的是四连问「想去哪个城市 / 计划玩几天 / 预算 / 一行几人」——
因为每一句都被当成独立的一句：`clarify_node` 只看当前 message，上一轮解析出的主体就地丢了
（`Session.history` 当时**只写不读**）。

| 机制 | 规矩 |
|---|---|
| **承接的四个守卫** | 只有「短（≤20 字）· 无已解析目的地 · 带疑问/属性提示 · 不含行程槽位与规划动词」**同时**成立才承接；任一不满足就 `None`（**绝不吞掉新请求**：「那去上海玩三天」仍是行程） |
| **承接什么** | 上一轮的**事实主体 + 地点 + 判别性实词**（主体定检索作用域，实词定落到哪批条目 —— 对话式查询扩展） |
| **自带主体就不许被覆盖** | 承接是「这一句**接不住自己**」时的兜底。判据只有一条：**命中片段之前切得出一个像样的主体吗**？切得出（「**华东师范大学**是不是有个新校区在那里」）就用它自己的；切不出（骨架在句首的「**是不是**还有一个校区」、占位名词「**具体位置**在哪儿」、指代碎片「**那个学校**怎么样」）才接上一轮。没有这条，「句子一长就接上一轮」会把用户新问的主体顶掉（真 bug 2026-10-04） |
| **什么不算「像样的主体」** | 空 / 单字 / 代词（`_DEGENERATE_SUBJECT`）/ 纯功能词骨架（`_FUNCTION_SKELETON`）/ 占位名词（`_PLACEHOLDER_NOUN`：位置、地址、附近…）/ **指代碎片**（`_is_anaphoric_fragment`：那个学校、那它、这个地方）。**只认「代词 + 通用名词 / 代词」这一形状**，否则会误伤真专名（「那不勒斯」也以「那」开头） |
| **方位指代** | 「那里 / 这里」解到上一轮那个**地方**：上一轮主体本身就是地名就用它（「上海临港」比城市级地点更精确），否则退到上一轮的地点。**只当地点上下文用，不动主体** —— 真 bug（2026-10-04）：「上海临港有哪些大学」→「华东师范大学**是不是有个新校区在那里**」自带新主体，整体承接会把主体覆盖成上一轮的（错）；指代解出来喂给模型（`{{context}}`）才是对的 |
| **上一轮原话与答复也进上下文**（`carry_context`） | 承接态下把「用户上一句问的是「…」，系统当时答的是「…」」一并塞进 `{{context}}`。真 bug（2026-10-04 审计 `7p1fi1`）：「它还有个滴水湖校区对吗」→「具体位置在哪儿」，主体接上了（华东师范大学）但模型看不到上一轮答复，只能答学校的通用位置，答不到用户真正问的那个校区。`prompts/answer.md` 规则 2 要「只回答问的那一件事」，前提是它知道上文在说什么 |
| **元问题** | 「刚才我说了什么」由 `recent` 轨迹**确定性**作答，不调模型（让模型看历史只会编） |
| **可见证据** | `GET /session/{id}` 返回槽位 + 轮次轨迹 + 最近主体，页面「会话记忆」面板读它 |
| **审计** | 每轮追加一行 JSONL 到 `.workbuddy/audit/turns-YYYY-MM-DD.jsonl`（写失败不影响主流程） |

已知取舍：承接存的是上一轮的 `intent.subject`（可能只是城市），不是显示焦点 ——
追问轮的卡片标题会退到主体粒度（「关于「上海」」）。检索仍落到正确条目，只是标题不如首问具体。

排查入口：审计 JSONL 只有 `message / type / subject`，**看不到答复与相关条目**。要判断
「回复异常」是哪一类，得用同一 `session_id` 把审计里的原话按顺序重放一遍
（`.ctrip-inbound/replay_*.py`），或直测 `detect_knowledge_intent(msg, settings, {}, hint_subject=…)`
把每一层判定打出来 —— 只看 `type` 会把「模型答歪」和「链路接错」混为一谈。

### 闸门按**问句骨架**收，不逐词补（`routes.yaml::intents.knowledge_question.triggers`）

同一个错误 —— **把「问事实」当成「排行程」** —— 到 2026-10-04 已经是第六形态了：

| 形态 | 例子 | 缺的那条骨架 |
|---|---|---|
| 一（实时） | 天安门什么时候升旗 | 时间/开放/天气词 |
| 二（静态） | 西湖有多大 | 度量/归属/定义词 |
| 三（寒暄） | 你好 | 独立意图 + 独立话术 |
| 四（是非问） | 华东师范大学**是不是**有个新校区在那里 | **系词「是不是」**（清单里只有「有没有 / 是否有」） |
| 五（评价/属性） | 上海博物馆**贵不贵 / 值不值得去 / 能不能带包** | **评价类「V不V」骨架**（清单里只有「是不是」一个 V不V） |
| 六（骨架在句首的**追问**） | （「华东师范大学在哪儿」之后）**是不是**还有一个校区 | 不是骨架没收到，而是**承接线索**没收到：这一句结尾没有「吗 / 呢 / ？」，`_FOLLOWUP_CUE` 里又没有「是不是 / 是否 / 有没有」，于是接不上上一轮的学校 → 三道闸门全灭 → 又掉回槽位体检 |
| 七（政策句继承了城市） | （「天安门升旗」之后）**240 小时过境免签**适用哪些国家 | `place` 是**库过滤条件**不是标题要素：承接来的 `place=北京` 把 `destination=中国` 的政策条目全滤掉了。修法是让政策层（`relevance: matched`）不继承任何地点 |

第六形态的教训与前面几条不同：**「按问句骨架收」要收两处** —— `routes.yaml` 的触发器
（决定「这是不是事实问询」）**和** `intent._FOLLOWUP_CUE`（决定「这一句接不接上一轮」）。
只补前者，独立的「上海博物馆是不是免费的」能答，承接式的「是不是还有一个校区」还是掉。

第五形态的兜底逻辑与前四种同源，但**在一句里出现两次**：① 骨架不命中 → 三道闸门全灭 →
掉回槽位体检；② 就算骨架命中了，触发片段常落在 **V不V 的中间**（「要不要**门票**」「收不**收费**」
「能不能用**信用卡**支付」），前半截切出**残片主体**（「上海博物馆要不」「能不能用」）。
残片在库里永远对不上，还会外溢成两处用户可见的错：卡片标题「关于「上海博物馆要不」」、
复核链接 Bing 搜「上海博物馆要不」。

| 规矩 | 理由 |
|---|---|
| 骨架清单要按**言语行为**收全（有无 / 是非 / 列举 / 度量 / 评价） | 这类问法无穷多，逐词补必然再漏 |
| **纯功能词骨架不得当主体**（`intent._FUNCTION_SKELETON`） | 命中片段落在句首时，`_subject` 会拿命中片段当主体 —— 那对「离境退税」这类**主题名**是对的，对骨架就是噪声（卡片标题会成「关于「是不是」」）。退化时退回槽位体检 |
| **剥「V不V」残片**（`intent._VV_RESIDUE`） | 触发片段落在骨架中间时，前半截末尾必是「<字>不<字>?」形状的残片 —— 只剥末尾、且只在骨架里剥，真实主体不受影响 |
| **剥前导骨架后退化 → 用命中片段当主体**（`intent._strip_leading_frame`） | 「能不能用信用卡支付」前半截是「能不能用」，剥掉骨架剩「用」（光杆）→ 退化。**只有这种「剥骨架剥出来的退化」**才改用命中片段（「信用卡」）；代词 / 纯骨架的退化仍退回槽位体检（否则全新会话首句「那要预约吗」会答成「关于「要预约」」） |
| 骨架不进实词/焦点 | `_TERM_STOP_RE` / `_LIGHT_CUE` / `_VV_FRAME` 一并收，否则标题尾巴会带出「是不是」「那里」、或焦点取到残片「要不」 |
| **承接态标题不拼焦点**（`display_topic`） | 追问自己没主体，只剩属性词（好吃/附近/学校），机械拼是「上海海事大学好吃」。判据：主体**是否原样出现在这一句** —— 不在就用主体当标签 |

### 「用户说清了却被反问」的第八形态：槽位**枚举**不敌**组合**（2026-10-05）

前七形态都是「这句话是不是在排行程」判错；第八形态是**句子判对了、句子里的一个数读错了**。
用户实测：系统追问「一行几个人、有没有老人和小孩」⟶ 用户答「只有我一个成年人」⟶ 没识别，又问一遍。

| 缺陷 | 根因 | 后果 |
|---|---|---|
| **① 抽不到** | 人数规则是**整串短语枚举**（`(\d+)\s*(?:个\|名)?\s*人`、`(\d+)\s*个大人`、`(\d+)\s*名成人`），要求数词 / 量词 / 身份词严丝合缝地相邻 | 「一个成年人」「1位成人」「两位成人」「就我自己」一个都抽不到 → 把用户刚答过的再问一遍 |
| **② 判反了** | 身份词**不认否定**，只看句中有没有「老人」「小孩」这几个字 | 「没有老人也没有小孩」→ 判定**有长者同行**。比抽不到更糟：行程会加载长者节奏叠加层，而且因为 `has_elder` 已知，追问里也不再问同行人构成 |

修法是承认**这三个维度正交**：数词 × 量词 × 身份词（`slots._PARTY_COUNT_RES`）。它们的组合随措辞
自由增长，靠加短语永远枚举不完 —— 这正是它和前七形态的差别：**那里缺的是一条条规则，这里缺的是语法**。
旧短语表降级为兜底（只在没拿到人数时才跑），因为它末尾那条「未识别 → 默认 2 大 1 小」兜底会盖掉已知人数。

否定按**分句**判（`slots._companion_flags`）：被否定的那一句整句跳过，别的小句照旧成立 ——
「没有，我带着爸妈去」仍算有长者同行。往 `SOLO_PHRASES` 里加「只有我」这种字符串捷径会命中
意思完全相反的「只有我们两个人」，所以代词式独行走的是**带负向断言的正则**。

**另外留了一条不依赖抽取的路**（用户提的方案）：口语怎么写都可能漏，所以 `POST /plan` 接受
`slot_overrides` —— 界面上的「行程信息卡」。三条来源的优先级是 **本句 > 表单 > 会话历史**：
本句最优先因为它最新、最明确；表单是这一轮刚填的；会话里的只补前两者没说的部分。
正规化见 `slots.slots_from_form`：**不是锦上添花，是抽不到时唯一能通的路**
（实测：一句里什么都没说、只填卡，也能直接出稿）。

### 「相关条目」的三类误召回（`app/knowledge.py`）

这一栏叫「知识库里的**相关**条目」，用的是**确定性词面打分**（不走向量、不调模型）。
它的每一次出错都是同一件事：**拿问法的字面去跟正文比字面**。

| 类 | 例子 | 修法 |
|---|---|---|
| **跨界假词** | 「校区**对吗**」切出「区对」→ 命中「领**区对**特定户籍」（韩国签证条目）；「收不**收费**」切出「收不」→ 命中「收不**到**短信」（eSIM 条目） | 摘掉句法成分再取 bigram：V不V 折词（`_VV_FOLD`）+ 是非问**确认尾**（`_CONFIRM_TAIL`：对吗 / 对吧 / 是吧 / 行吗）。**顺序有讲究** —— 确认尾必须先于折词摘，否则「对不对」会被折成一个光杆「对」继续惹事 |
| **占位名词当实词** | 「**具体位置**在哪儿」的「位置」→ 命中住宿条目的「**位置**优先于房型」；「有多大」的「多大」同理 | 问法不是主题：`_TERM_STOP_RE` 收「具体位置 / 详细地址 / 位置 / 地址 / 具体 / 详细」等 |
| **通用成分当主体** | 「华东师范大学」的成分 bigram「大学」→ 命中「厦门**大学**一带」（厦门地铁条目） | 「沾主体」判定改用 `_related_keys`：**整个主体 + 去掉通用成分**（`_GENERIC_COMPONENT`：大学 / 学院 / 公司 / 广场…）。这一条的后果不只是多一条噪声 —— 「本库对它一无所知就返回空」那道闸门依赖它，误触发之后**整张候选表**（住宿省钱 / 韩国签证）都会被当成相关条目列出来 |

判据：**主体对不上、问句又只贡献了通用词 → 宁可空着**（文案会明说「本库没有关于它的材料」）。
空是诚实的信息；拿别的话题凑数是误导。

### 权威入口的名实一致（`routes.yaml::intents.realtime_fact.channels`）

真 bug：`name` 写《天安门广场升旗仪式观看指南》、`url` 写站点根 —— 点开必然跳首页。

| 规矩 | 理由 |
|---|---|
| `name` 必须描述**点击后落在哪儿** | 名字承诺文档、链接却到首页 = 骗人。落到站点根的入口，名字里要写明「站内搜…」 |
| `region` 写入口**实际覆盖的范围**，不是国家 | 北京那条写成「中国」时，杭州问开门也会拿到它 —— 给错地方的官方入口比不给更坏 |
| 地点解析不出来时只给**无 region 的通用入口** | `_channels_for` 的兜底。一条都不剩就走「暂无已核实的权威入口」文案 —— 那是诚实的空缺 |
| 地名解析靠**地标别名**（鼓浪屿→厦门、西湖→杭州） | 解析不出地名就没法按地区筛入口（上一条的根因） |

原文链接由**命中的条目自带**（`facts[].source_url`），页面渲染成可点的编号 chip；
`channels` 只是「去哪儿查」的入口点，两者在文案上明确区分。

## 4. 检索：三层配额

`retrieval.layer_quota` = `general 0.2 / scene 0.5 / realtime 0.3`，签证场景覆盖为
`0.2 / 0.2 / 0.6`（时效信息权重更高）。

流程：**元数据预过滤**（目的地/场景/时效）→ **向量召回**（`top_k=14`，
候选池 = `top_k × candidate_multiplier = 84`）→ **按层配额截断**。

**检索查询恒为中文**（知识库是中文语料）；查询跟着用户语言走会崩召回。
这一点与「输出语言跟用户」是两条独立的边界。

**场景 → 知识范围**（`knowledge_scopes`）决定预过滤放行哪些层：

| 场景 | scopes |
|---|---|
| general | `general` + `scene:*`（整层通配） |
| family / budget / roadtrip | `scene:<自己>` + `general` |
| visa | `scene:visa` + `realtime:visa` |

general 必须带 `scene:*`：绝大多数目的地知识落在 scene 层（种子里厦门 7 条在 scene、
只有 3 条在 general），只查 general 会让最常见的请求拿到最少的知识，层配额里给 scene
留的 0.5 也永远空着。`scene:*` 是整层通配 —— 内存库 `_scope_match` 与 SQL `_where`
两侧语义必须一致（有测试钉住）。

## 5. 校验：三项并行

| 检查 | 判据 |
|---|---|
| Budget | 分项合计 vs 预算 ×（1 + 缓冲比例） |
| Fact | 行程里的具体断言能否溯源到引用；不能则降级为「待核实」 |
| Consistency | 天数/预算/同行人等内部自洽 |

`severity` 是**配置上限**（none/warn/repair/block），`status` 是**本次结果**。
一条 pass 的 budget 检查仍会报 `severity=repair`。

## 7. 一次请求的时序

```
POST /plan
  行程主干
  → clarify      意图判定 + 确定性抽槽（含会话槽位合并）   0.0s
  → classify     小模型分类                              ~1–3s
  → route        生成 RouteConfig                         0.0s
  → retrieve     embedding + 向量召回（可分批）            ~1–3s
  → generate     大模型生成                              ~15–40s
  → validate     三项校验                                0.0s（不调模型）
  → output

  实时事实旁路（命中意图闸门时，上面五步都不跑）
  → clarify      意图判定                                0.0s
  → realtime     扫实时层 + 两道闸门                      0.006–0.028s（实测）
  → output

  常识旁路（同样五步不跑）
  → clarify      意图判定（含咨询兜底）                     0.0s
  → knowledge    扫 scene/general → 模型通用常识作答         0.6–0.9s（实测，含一次模型调用）
  → output
```

真实模型单条合计约 20–60 秒；缺槽短路与实时旁路都是亚秒级，
常识旁路约 0.6–0.9 秒（一次短提示词调用，比出稿少一个数量级）。
追问承接（读内存轨迹 + 抽实词）与审计落盘都是亚毫秒级，不改变上面的量级。

## 8. 明确的边界（本期不做）

| 项 | 状态 |
|---|---|
| 会话持久化 | 进程内，重启即丢（槽位 / `recent` 轨迹 / 最近主体都只在内存；审计 JSONL 落盘，但不是读取来源） |
| 追问承接的粒度 | 承接的是上一轮 `intent.subject`（可能只是城市），不是显示焦点 —— 追问轮的卡片标题会退到主体粒度（「关于「上海」」）。检索仍落到正确条目 |
| 追问承接的判据 | 靠**确定性守卫**（短 / 无地名 / 带疑问 / 无行程槽位），不是语义理解。省略得更狠的追问（如「多少钱」接在纯闲聊后）不承接 → 老老实实追问 |
| 指代解引用的范围 | 只认**方位指代**（那里 / 这里 / 那儿 / 这儿 / 那边 / 这边 / 此地），且只回指**上一轮**，且会话里得真有对象。名词性指代（「那个学校」「它」）与更长的指代链不处理 |
| 指代的作用面 | 解出来的地名只进**常识作答的上下文与地点记忆**，不进检索实词（避免把指代前面的问句话题混进「相关条目」）。实时旁路未接 —— 「开放时间呢」靠主体承接，不靠指代 |
| 真实汇率换算 | 「5000円 / 5000원」只取数字，不换算（没有汇率源） |
| 工具 | 只有 3 个，且都在白名单里，模型不能自造工具 |
| 多语言 | zh / en 完整可用；ja / ko 属「能进 plan，内容质量看模型」 |
| 语言硬保证 | 模型不保证 100% 遵守语言段；要硬保证需加后置检查（每轮多一次生成调用），未做 |
| 预算下限类表述 | 「预算下限 8000」抽不到（正则要求预算后紧跟数字） |
| 事实问询的判定覆盖面 | 靠**确定性正则骨架** + 一条咨询兜底（有目的地 + 疑问语气）。骨架清单（有无 / 是非 / 列举 / 度量 / 时间 / 定义）仍是有限集，没被覆盖的问句（如「今天股市怎么样」，既无目的地也无闸门命中）仍走行程链路 → 会被追问行程槽位。要覆盖新句式就往 `routes.yaml::intents` 加骨架正则，**不把意图判定改成调模型**（那会引入随机性：同一句话两次跑出两种意图） |
| 常识作答的准确度 | 答案来自模型通用常识，**未经本库核实**（响应里如实标注 + 给复核入口）。稳定常识（面积 / 海拔 / 历史）风险低，但没有自动校验；时效性信息按提示词拒答 |
| 常识作答的字段边界 | 模型可能多给一句无关的补充（如「绕湖一周约 15 公里」）。提示词要求只答问的那件事，但不做后置裁剪 |
